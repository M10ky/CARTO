--------------------------------------------------------------------------------
1. OBJECTIF DU PROJET
--------------------------------------------------------------------------------

Construire une application web de cartographie physique du Cluster CNTO :

  - reproduire fidèlement le plan (zones, rangées, allées, blocs) de la
    référence Excel "Feuille de calcul sans titre.xlsx" ;
  - y associer des positions (postes), des collaborateurs, le parc informatique
    et les interventions de maintenance ;
  - fournir un tableau de bord, un plan interactif, des fiches et des
    statistiques ;
  - ajouter l'import Excel / CSV, l'authentification et la gestion des rôles ;
  - rester maintenable : données / logique métier / rendu / interactions
    séparés.

Public : personnel encadrant du cluster (consultation, inventaire,
administration).


--------------------------------------------------------------------------------
2. RÈGLES DE TRAVAIL À RESPECTER ABSOLUMENT
--------------------------------------------------------------------------------

Ces règles viennent du prompt maître du projet ; elles sont non négociables.

  1. Jamais tout générer d'un coup. Une étape à la fois, vérifiable
     (build + lint + typecheck), puis attendre la validation de l'utilisateur
     avant la suivante.
  2. Géométrie fidèle à l'Excel. La disposition réelle des zones/rangées doit
     être reprise du .xlsx. Il est INTERDIT de la remplacer par une grille
     générique régulière. Ne pas réutiliser buildSeats() de
     cartographie-cluster.html (Math.ceil(total / rows) + noms inventés).
  3. Aucune donnée fictive en production. Pas de KPI, ni de liste, ni de poste
     inventés : les écrans vides doivent l'assumer (état vide, mention
     "provisoire").
  4. Séparation stricte : données spatiales / données métier / rendu / interactions.
  5. Thème différent de la géométrie : le thème doit pouvoir changer sans
     toucher aux coordonnées du plan.
  6. Permissions appliquées côté serveur, doublées par RLS dans Supabase.
     Ne jamais se fier au seul masquage d'interface.
  7. Ne jamais désactiver TypeScript, ESLint ou RLS pour contourner un problème.
     Corriger la cause.
  8. Ne pas commiter sans demande explicite de l'utilisateur.
  9. Aucun commentaire dans le code (convention du projet) sauf nécessité
     réelle documentée.

4. COMMANDES UTILES
--------------------------------------------------------------------------------

  npm install                 dépendances
  npm run dev                 serveur de développement (http://localhost:3000)
  npm run lint                ESLint
  npm run typecheck           tsc --noEmit
  npm run build               build de production
  npm test                    tests sécurité puis bout en bout (node --test)
  npm run test:security       tests RLS/sécurité (base live + statique)
  npm run test:e2e            tests HTTP (rebuild puis next start)

Ordre recommandé avant toute validation d'étape :
  npm run lint && npm run typecheck && npm run build && npm test

Remarque : si typecheck remonte des erreurs dans .next/types/... après
modification des routes, supprimer .next/ (rm -rf .next) puis relancer :
ce sont des types générés obsolètes, pas des erreurs de code.

9. PROBLÈMES CONNUS / ARBITRAGES RESTANTS
--------------------------------------------------------------------------------

  1. Import Excel : xlsx@0.18.5 (26 vulnérabilités, 2 critiques) RÉSOLU en
     Phase 7 : remplacé par exceljs@4.4.0 (serveur uniquement). L'audit npm
     restant provient de l'outillage framework/CLI (next,
     @modelcontextprotocol/sdk…) — hors périmètre import.
  2. Dossier ~/package.json orphelin hors dépôt : warning Turbopack atténué par
     turbopack.root dans next.config.ts ; suppression manuelle recommandée.
  3. skills/, .claude/skills/, .windsurf/skills/ contiennent la doc Prisma alors
     que Prisma est retiré : à supprimer après accord utilisateur.
  4. Écarts de volumétrie (voir docs/cartographie-phase3.md §3) : plan dessiné
     (671) vs compteurs Excel vs prototype (631) vs Récap IT (627).
  5. Bloc central (lignes 25-34, libellés horizontaux) : géométrie à valider.
  6. Grandes fusions vides et 23 ancrages d'images (6 PNG) : nature à identifier.
  7. Zone 9 : compteur 90 vs 41 positions dessinées (écart -49).
  8. `supabase link` échoue (compte CLI sans droits) : contourné en poussant les
     migrations via `supabase db push --db-url` à travers le **Session pooler**
     `aws-0-eu-west-1.pooler.supabase.com` (l'hôte direct `db.*` n'est qu'en IPv6).
     Le mot de passe DB n'est stocké dans aucun fichier.
